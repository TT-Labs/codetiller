The command line tool is `tiller`. The web UI does most of what the task commands do; installation, checks and evals are command line only.

## How to invoke tiller

The docs write `tiller …`. What you type depends on the installation:

| Installation | Command |
| --- | --- |
| From a clone | `pnpm tiller …` |
| Docker on a server | `docker compose -f deploy/compose.yaml exec tiller tiller …` |
| Kubernetes | `kubectl -n tiller exec deploy/tiller -- tiller …` |

Commands act on the working directory they run in: its `tiller.db`, `artifacts/`, `.cache/`, `.env` and `tiller.yaml`. In a container installation that is already set.

`tiller <command> --help` prints the options of a command.

## Running the factory

| Command | What it does |
| --- | --- |
| `tiller ui` | Starts the API, the web UI and the worker, and prints the link with the API token. |
| `tiller daemon` | The worker without the UI: imports labelled issues, follows pull requests, executes the runs humans queued. |
| `tiller task run` | Executes queued runs in the foreground until the queue is empty. |

Run one of the three at a time on a working directory.

Options of `tiller ui`:

| Option | Default | Meaning |
| --- | --- | --- |
| `--port <port>` | `4317` | The port to listen on. |
| `--host <address>` | `127.0.0.1` | The address to listen on. `0.0.0.0` in a container whose port the host publishes. |
| `--url <url>` | | The address people open the UI at, when it is not this machine: a reverse proxy, a server name. |
| `--api-only` | | Serve the API only, for developing the web UI. |

## Installation and checks

| Command | What it does |
| --- | --- |
| `tiller doctor` | Checks the installation: runtime, sandbox image, workspaces, credentials, repositories. Exit 1 when a check fails. See [Operations](/docs/operations#doctor). |
| `tiller setup` | Docker hosts: builds the sandbox image when it is missing, then runs `doctor`. `--rebuild` builds it even when there is one. |
| `tiller audit` | Probes the trust boundary inside the containers the factory starts, without a model call. Exit 1 on a failed probe. See [Operations](/docs/operations#audit). |
| `tiller gateway stop` | Docker hosts: removes the model gateway and registry proxy containers. The next run starts fresh ones. |
| `tiller tools` | Lists commands agents tried that the sandbox images lack, from run transcripts. |

Options of `tiller audit`:

| Option | Default | Meaning |
| --- | --- | --- |
| `--image <image>` | the sandbox base image | The image that is probed. |
| `--profile <name>` | | Probe the image of the sandbox profile `datasets/<name>` instead. |
| `--config <name>` | `c0-vanilla` | The agent config the audited run is opened with. |
| `--port <port>` | `4317` | Where the factory's API listens. |

## Repositories

| Command | What it does |
| --- | --- |
| `tiller repo add <owner/name>` | Onboards a repository: takes its `.factory/factory.yaml` or proposes a sandbox profile, installs its dependencies and runs its tests once. Exit 2 when the profile does not run. |
| `tiller repo list` | Onboarded repositories and how their last baseline check went. |
| `tiller repo remove <owner/name>` | Forgets an onboarded repository. Its tasks stay. |

Options of `tiller repo add`:

| Option | Default | Meaning |
| --- | --- | --- |
| `--config <name>` | `c0-vanilla` | The agent config of its tasks. |
| `--label <label>` | `tiller` | Issues with this label are imported. `none`: no intake. |
| `--no-check` | | Do not install and run the tests. |

See [Add a repository](/docs/repositories).

## Tasks

### Create and queue

| Command | What it does |
| --- | --- |
| `tiller task create --repo <owner/name> --title <title>` | Creates a task in state `IMPORTED`. Nothing runs until it is queued. |
| `tiller task import` | Imports labelled issues now. Imported tasks are not queued. |
| `tiller task enqueue <id> [message...]` | Queues a run. The message — an answer, feedback — goes to the agent. |
| `tiller task split <id>` | Approves the split the preflight proposed: its parts become tasks, the original is cancelled. |
| `tiller task complete <id>` | Marks a task completed. |
| `tiller task cancel <id>` | Cancels a task. |

Options of `tiller task create`:

| Option | Default | Meaning |
| --- | --- | --- |
| `--repo <owner/name>` | required | The repository. |
| `--title <title>` | required | The task's title. |
| `--body <text>` | | The description. |
| `--body-file <file>` | | Read the description from a file. |
| `--config <name>` | `c0-vanilla` | The agent config. |
| `--ref <ref>` | the default branch | The branch to start from. |
| `--model <id>` | | Run on this model instead of the default. One of `factory.models`. |
| `--enqueue` | | Queue the first run right away. |
| `--dataset <name>` | | Use the sandbox profile `datasets/<name>/profile.yaml` of the working directory instead of the repository's own. |

Options of `tiller task enqueue`:

| Option | Meaning |
| --- | --- |
| `--no-preflight` | Start the first run without the read-only assessment. |
| `--model <id>` | Run on this model from now on. `default`: back to the default. |
| `--out-of-order` | A part of a split: start without waiting for the part before it. |

### Look

| Command | What it does |
| --- | --- |
| `tiller task list` | All tasks with their state. |
| `tiller task show <id>` | The timeline of a task: human messages, agent questions and summaries, runs. |
| `tiller task manifest <runId>` | What a run was made of: repository commit, skills, model, image, prompt. `--check` verifies every input is still there and unchanged; exit 1 on drift. |
| `tiller task metrics` | Delivery, first pass, human interventions and cost, over all tasks and per repository, config and model. |

### Pull requests, verification, CI

| Command | What it does |
| --- | --- |
| `tiller task sync` | Reads pull request feedback now: queues tasks with a new `/tiller` comment, closes merged and closed ones. |
| `tiller task update <id>` | Brings the default branch into the task. A clean merge is verified and pushed; conflicts are queued for the agent. |
| `tiller task verify <id>` | Verifies the task branch again without an agent run, and pushes when it passes. |
| `tiller task ci <id>` | What the repository's CI says about the task's pull request. `--fix` sends the failing checks and the end of their logs to the agent. |
| `tiller task review <id>` | Runs the second reader on its own. Nothing is recorded on the task. |

Options of `tiller task verify`:

| Option | Meaning |
| --- | --- |
| `--accept-removed` | The tests the last verification found removed may go. |
| `--accept-checks` | The changed files that decide the checks are fine: no second run with the old ones. |

Options of `tiller task review`:

| Option | Meaning |
| --- | --- |
| `--base <commit>` | Read the change from this commit. Default: the task's base. |
| `--head <commit>` | Up to this commit. Default: the head of the task branch. |
| `--json` | Print the report as JSON. |
| `--task-only` | Give the reader the task text without the human messages that came later. |

### Models and experiments

| Command | What it does |
| --- | --- |
| `tiller task model` | Prints the default model and the models on offer. |
| `tiller task model <model>` | Sets the default. `none`: each task's config decides. |
| `tiller task model <id> <model>` | Sets the model of one task, from its next run. `default`: no own choice. |
| `tiller task experiment <ids...>` | Marks tasks as experiments, left out of the metrics. `--off` unmarks them. |

## Evals

| Command | What it does |
| --- | --- |
| `tiller benchmark --dataset <name> --config <name>` | Runs a config over a dataset, in parallel, with a hard budget cap. |
| `tiller run --task <id> --config <name> --dataset <name>` | One task, one config: agent in the sandbox, verification, stored. `--dataset <name>` names the dataset; `--keep-workspace` keeps the workspace. |
| `tiller compare <a> <b>` | Paired per-task comparison of two benchmarks. `--split train\|holdout\|all`. |
| `tiller gate <baseline> <candidate>` | The eval gate for a skill or config change: evidence as markdown. Exit 2 when the rule says keep. |
| `tiller noise --dataset <name>` | Rerun noise of a dataset from stored benchmarks: what delta a comparison can detect, at what cost. |
| `tiller improve --benchmark <name> --dataset <name> --skill <name>` | Failed train runs → labelled clusters → a proposed learned skill, for review. |
| `tiller config add <file>` | Resolves an agent config and prints its content hash. |
| `tiller skill generate --dataset <name> --at <commit> --name <name>` | An agent writes an onboarding skill from the repository at a commit. |

Options of `tiller benchmark`:

| Option | Default | Meaning |
| --- | --- | --- |
| `--split <split>` | `all` | `train`, `holdout` or `all`. Needs the dataset's `split.yaml`. |
| `--repeats <n>` | `1` | Runs per task. |
| `--concurrency <n>` | `3` | Parallel runs, each about 2 CPUs and 4 GB. |
| `--budget <usd>` | `10` | Stop starting runs once this much is spent. |
| `--name <name>` | | A name for the benchmark. |
| `--only <ids>` | | Comma-separated task ids. |

Options of `tiller gate`:

| Option | Default | Meaning |
| --- | --- | --- |
| `--split <split>` | `all` | `train`, `holdout` or `all`. |
| `--out <file>` | stdout | Write the evidence to a file. |
| `--reference <benchmark>` | | The config from before any promotion: the candidate must not be below it by more than rerun noise either. |

Options of `tiller noise`:

| Option | Default | Meaning |
| --- | --- | --- |
| `--metric <name>` | `success` | `success`, or a per-run metric of `tiller compare`. |
| `--delta <x>` | `0.05` | The effect to plan for, in units of the metric. `0.05` is five percentage points. |

Options of `tiller improve`:

| Option | Default | Meaning |
| --- | --- | --- |
| `--split <split>` | `train` | Learn only from this split. |
| `--max-words <n>` | `500` | The size limit of the proposed skill. |

Options of `tiller skill generate`:

| Option | Default | Meaning |
| --- | --- | --- |
| `--config <name>` | `c0-vanilla` | The agent and model that write the skill. |
| `--prompt <file>` | `prompts/onboarding.md` | The prompt for writing it. |

See [Evals](/docs/evals).

## Datasets

| Command | What it does |
| --- | --- |
| `tiller dataset mine <dir> --repo <owner/name>` | Proposes task drafts from merged pull requests that close an issue and change tests. `--since <date>`, `--limit <n>` (default 300 pull requests scanned). |
| `tiller dataset infer <dir>` | Drafts → tasks: runs the hidden tests at base and fix, derives the tests that must go from failing to passing, keeps the valid ones. `--repeats <n>` (default 2), `--only <id>`. |
| `tiller dataset validate <dir>` | The oracle check per task: hidden tests fail at base, pass at fix. `--task <id>`, `--repeats <n>` (default 2). |
| `tiller dataset split <dir>` | A seeded train and holdout split, written to `split.yaml`. `--holdout <ratio>` (default 0.4), `--seed <n>` (default 1). |
| `tiller dataset audit <dir>` | Curation evidence per task from stored runs, without agent runs. |

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | Done. |
| `1` | An error, or a failed check: `doctor`, `audit`, `task manifest --check`, a sync or import with errors. |
| `2` | A negative answer that is not an error: `repo add` when the profile does not run, `gate` when the verdict is to keep the baseline. |

## Not implemented

`tiller review`, `tiller runs` and `tiller show` exist as names and print that they are not implemented yet.
